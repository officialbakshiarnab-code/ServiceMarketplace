## Application Startup Sequence

### OLD: Role Creation on Demand
```
???????????????????????????????????
?  Application Starts             ?
???????????????????????????????????
?  1. Build configuration         ?
?  2. Register services           ?
?  3. Build WebApplication        ?
?  4. Apply migrations            ?
?  5. Middleware setup            ?
?  6. Start listening             ?
???????????????????????????????????
        ?
   First user registers
        ?
   AuthService.RegisterAsync()
        ?? Create user
        ?? ??  Check if role exists
        ?? ??  CREATE ROLE  ? Problem: delays registration
        ?? Assign role
        ?? Return
```

**Issues**:
- ? Roles created on first use (lazy initialization)
- ? Delays first user registration
- ? Race conditions if multiple users register simultaneously
- ? Hard to verify roles exist

### NEW: Role Creation at Startup
```
???????????????????????????????????
?  Application Starts             ?
???????????????????????????????????
?  1. Build configuration         ?
?  2. Register services           ?
?  3. Build WebApplication        ?
?  4. Apply migrations            ?
?  5. ? SEED ROLES (NEW!)         ?
?     ?? Create User role         ?
?     ?? Create ServiceProvider   ?
?     ?? Create Admin role        ?
?  6. Middleware setup            ?
?  7. Start listening             ?
???????????????????????????????????
        ?
   First user registers
        ?
   AuthService.RegisterAsync()
        ?? Create user
        ?? ? Verify role exists
        ?? Assign role
        ?? Return
```

**Benefits**:
- ? Roles created once at startup
- ? Fast user registration (no role creation)
- ? No race conditions
- ? Easy to verify initialization

## User Registration Flow

### OLD: Role Creation During Registration
```
User submits registration
        ?
AuthController.Register()
        ?
AuthService.RegisterAsync()
        ?? Validate email/password
        ?? Start transaction
        ?? Create user
        ?? ??  Check if role exists
        ?     ?? If not, CREATE IT
        ?? Assign role
        ?? Commit transaction
        ?
Return response
```

### NEW: Role Verification Only
```
User submits registration
        ?
AuthController.Register()
        ?
AuthService.RegisterAsync()
        ?? Validate email/password
        ?? Start transaction
        ?? Create user
        ?? ? Verify role exists
        ?    ?? If not, return error
        ?? Assign role
        ?? Commit transaction
        ?
Return response
```

## Exception Handling Flow

### OLD: BidsController Exceptions
```
PlaceBid() endpoint
        ?
    Get claims
        ?
Missing claim?
  ?? YES ? throw UnauthorizedAccessException
  ?         ?? 500 Internal Server Error
  ?? NO  ? Continue
```

### NEW: BidsController Proper Responses
```
try {
    PlaceBid() endpoint
            ?
        Get claims
            ?
    Missing claim?
      ?? YES ? return Unauthorized (401)
      ?? NO  ? Process bid
               ?? return Ok (200)
}
catch (ArgumentException)  ? return BadRequest (400)
catch (InvalidOperation)   ? return BadRequest (400)
catch (Exception)          ? return BadRequest (400)
```
