## Duplicate Prevention Index Strategy

```
??????????????????????????????????????????????????????????????????????
?              DATABASE INDEX FOR DUPLICATE PREVENTION               ?
??????????????????????????????????????????????????????????????????????

AuditLogs Table Indexes:
?????????????????????????

1. PRIMARY KEY
   ?? [Id] (GUID)
   ?? Ensures uniqueness per entry

2. IX_AuditLogs_SessionId ? (USED FOR DUPLICATE CHECK)
   ?? Column: SessionId (NVARCHAR(100))
   ?? Type: Non-clustered
   ?? Purpose: Fast lookup to check if SessionExpired already exists
   ?? Query:
      SELECT * FROM AuditLogs
      WHERE SessionId = @sessionId
      AND EventType = 'SessionExpired'
      ?? Uses index ? ~O(log n) instead of O(n) full table scan

3. IX_AuditLogs_UserId
   ?? Column: UserId
   ?? Purpose: Query audit trail per user
   ?? Example: Get all user's audit events

4. IX_AuditLogs_TimestampUtc
   ?? Column: TimestampUtc (DESC)
   ?? Purpose: Recent events first
   ?? Example: ORDER BY TimestampUtc DESC

DUPLICATE PREVENTION FLOW:
?????????????????????????

  POST /token-expired arrives
         ?
         ?
  Extract SessionId = "guid-abc-123"
         ?
         ?
  Query AuditLogs WHERE SessionId='guid-abc-123'
  AND EventType='SessionExpired'
         ?
         ?? Use IX_AuditLogs_SessionId
         ?  ?? Fast lookup (milliseconds)
         ?
         ?
  Row found?
  ?? YES ? Return (skip insert)
  ?         Prevents duplicate ?
  ?
  ?? NO  ? INSERT new entry
            Creates audit trail ?

PERFORMANCE:
?????????????
• Without index: ~50ms per query (full table scan)
• With index: ~2ms per query (B-tree search)
• Improvement: 25x faster duplicate detection
```
